# 无提单禁建门闸说明（当日封死）

- 拍板日期：2026-11-24
- 案号：提单案戊（无单禁建第 5 号）
- 状态：**已封死，全仓只认一种写路径，两边不得混用，无第三路。**

## 一、口径拍板：甲路径

提单册（`bl_manifests`）无匹配行时，过磅写口：

1. **正式册（`weigh_tickets`）零增**；
2. **拒收**并返回 422 `无提单禁建：提单册无匹配行，正式册零增并拒收`；
3. 审计轨迹记一条 `无提单禁建偏航`，`target` 为提单号；
4. 不设影子待挂票、不设事后晋升、不允许任何旁路写正式册。

乙路径（无提单写影子票、待提单登记后晋升）**已否决，不实现**。甲乙混用会让无提单
仍出正式票，故全仓只保留甲路径这一种写入口径。

## 二、三层门闸（同一写入口径）

| 层 | 位置 | 行为 |
| --- | --- | --- |
| 服务层 | `backend/tickets_svc.py` `POST /api/tickets` | 提单册查无匹配行即拒，正式册零增，写 `无提单禁建偏航` 审计 |
| 库表层 | `backend/db.py` `weigh_tickets.bl_ref` 外键 → `bl_manifests.bl_code` | 任何绕过服务的直插/种子写入均触发 `IntegrityError`，正式册物理上无法落无单票 |
| 种子层 | `backend/db.py` `seed_tickets` | 提单册无匹配行的夹具票同口径跳过，文件库夹具不得污染正式册 |

存量库由 `_migrate_ticket_bl_fk` 按 SQLite 官方 12 步重建表补外键，行不丢、可重复、
重建后跑 `PRAGMA foreign_key_check` 复检。

## 三、提单锁与争用

- 锁键：`bl:<提单号>`，与既有车道锁 `lane:<车道id>` 在同一立即写事务内获取，
  锁序固定为「先车道锁、后提单锁」，释放在 `finally` 中按反序进行。
- 双会话同提单号（含跨车道）抢建票：库级写锁串行，只许一票落地；
  后到者在 `contention_log` 留 `争用` 痕并收 409，不写任何业务数据。
- 争用痕在锁事务内随正常 `commit` 落盘；业务事务另起，回滚不影响争用痕。
- `locks.try_acquire` 改 `INSERT OR IGNORE` 单语句抢占，消除先查后插竞态。

## 四、五页同源

过磅页、提单页、对账页、车道页、总览页的数据源均为带外键的正式册：

- 对账（`reconcile_svc`）汇总正式票时 `JOIN bl_manifests`，无提单孤儿票不可能计入
  在港毛重；事后补登记提单也不追溯累计历史无单票。
- 过磅页、车道页、总览页的票量直接取自正式册，门闸拦截后五页一致为空/不增。
- 前端过磅页在提单册为空时禁用「过磅入闸」并提示，仅为后端门闸的联动，不替代门闸。

## 五、偏航处置

任何偏离甲路径、试图让无提单数据进入正式册的写法，统一记 `无提单禁建偏航` 并拒写。
禁止只改前端提示条；禁止无测试改灰字（无对应红测的代码改动不得合入）。
